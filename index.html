TDS Project 1 Learnings

Building a GitHub Pages Automation Project

Recently, I worked on automating GitHub Pages deployment and faced several challenges along the way. Here are the key lessons I learned that might help others on a similar journey.

Problem 1: New Replit Interface

Issue

Replit changed their UI and the "Create Repl" button was no longer visible. The new AI-powered interface was confusing to navigate.

Solution

I decided to use VS Code with local Python instead. I used ngrok to make the local server publicly accessible, which gave me more control without depending on Replit's interface.

Alternative approach

You can also click the "+ Create App" button (which is the new name for Create Repl) or use the "General" tab with an AI prompt to auto-setup.

Problem 2: OpenAI API Key Not Free

Issue

OpenAI requires payment after the free credit expires (limited to 3 months). I encountered this error:

{ "openai_key_valid": false, "openai_error": "Invalid OpenAI key" }
Solution

I switched to Google Gemini API, which is completely free with generous limits (1,500 requests/day). Updated the code to use Gemini instead of OpenAI.

Code changes

# BEFORE (OpenAI) import openai openai.api_key = OPENAI_API_KEY response = openai.ChatCompletion.create(model="gpt-3.5-turbo", ...) # AFTER (Gemini) import google.generativeai as genai genai.configure(api_key=GEMINI_API_KEY) model = genai.GenerativeModel('gemini-2.0-flash-exp') response = model.generate_content(prompt)

Package change

pip uninstall openai pip install google-generativeai

Problem 3: Gemini Model Name Outdated

Issue
404 models/gemini-pro is not found for API version v1beta

The old model name gemini-pro was deprecated and the documentation was outdated.

Solution

Updated to newer model names. I tried these in order:

  1. gemini-1.5-flash (didn't work)
  2. gemini-1.5-pro (didn't work)
  3. gemini-2.0-flash-exp (worked!)

Fix

# Update in TWO places in main.py: model = genai.GenerativeModel('gemini-2.0-flash-exp')

Problem 4: GitHub Token Insufficient Permissions

Issue
403 Forbidden "Resource not accessible by personal access token"

The token was created without proper permissions, so I couldn't create repositories.

Solution

Created a new GitHub token with all required scopes:

  • repo (full control - most important)
  • workflow
  • admin:repo_hook
  • delete_repo

Steps to create token

  1. Go to https://github.com/settings/tokens
  2. Generate new token (classic)
  3. Check all sub-boxes under "repo"
  4. Copy token immediately (starts with ghp_)
  5. Update in main.py

Problem 5: Repository Creation Conflict

Issue
422 Invalid request. "sha" wasn't supplied.

Using auto_init=True creates a default README, but then the code tries to create README again, causing a conflict.

Solution

Changed auto_init=False and manually created all files in the correct order with branch="main" parameter.

Code fix

# BEFORE repo = user.create_repo(repo_name, auto_init=True) # AFTER repo = user.create_repo(repo_name, auto_init=False) repo.create_file("LICENSE", "Add LICENSE", content, branch="main") repo.create_file("README.md", "Add README", content, branch="main") repo.create_file("index.html", "Add website", content, branch="main")

Problem 6: Ngrok 503 Service Unavailable

Issue
503 ERR_NGROK_3004 The server returned an invalid or incomplete HTTP response

The Flask app crashed or stopped, and ngrok couldn't connect to it.

Solution

Always check the Flask terminal first for Python errors. Restart Flask with Ctrl+C then python main.py. Verify that ngrok is pointing to the correct port (5000) and keep both terminals running.

Verification steps

  1. Flask shows: Running on http://0.0.0.0:5000
  2. Ngrok shows: Forwarding https://...ngrok.io -> localhost:5000
  3. Test by visiting the ngrok URL in browser

Problem 7: Test Script Returns 405

Issue
Status: 405 JSONDecodeError: Expecting value

Used localhost instead of ngrok URL in the test script, and was missing the /api-endpoint path.

Solution

Updated test_api.py with the correct ngrok URL:

# WRONG API_URL = "http://localhost:5000/api-endpoint" # CORRECT API_URL = "https://your-ngrok-url.ngrok-free.dev/api-endpoint"

Problem 8: Browser Shows "Method Not Allowed"

Issue

Visiting /api-endpoint in browser showed "Method Not Allowed" and I thought the endpoint was broken.

Solution

This is actually correct behavior! The /api-endpoint only accepts POST requests, while browsers send GET requests. This proves the endpoint is working properly.

Verification

  • Root URL (/) works in browser
  • Test URL (/test) shows config status
  • API endpoint rejects browser requests (correct)
  • POST requests via script work (perfect)

Complete Setup Checklist

Prerequisites

  • Python 3.x installed
  • GitHub account created
  • GitHub Personal Access Token with repo permissions
  • Google Gemini API key (free)
  • Ngrok account and installed

Project Files

  • main.py - Flask API server
  • test_api.py - Testing script
  • requirements.txt - Package dependencies

Configuration in main.py

  • YOUR_SECRET - Custom password
  • GITHUB_TOKEN - Token with full repo permissions
  • GEMINI_API_KEY - Google AI Studio key
  • GITHUB_USERNAME - Your GitHub username

Running the project

  • Terminal 1: python main.py (Flask)
  • Terminal 2: ngrok http 5000 (Public URL)
  • Keep both running during evaluation

Testing

  • Visit ngrok URL /test endpoint
  • Run python test_api.py
  • Check GitHub for new repo
  • Check Pages deployment (wait 2-5 min)

Key Learnings

Use Gemini instead of OpenAI: It's completely free with no credit card needed and has generous limits (1,500 requests/day). The latest model is gemini-2.0-flash-exp.

GitHub tokens need full permissions: Always check the entire repo scope and include workflow and admin:repo_hook. Test the token immediately after creation.

Use auto_init=False: This avoids file creation conflicts. Create files manually in order and always specify branch="main".

Local development is better than Replit: You get more control over the environment without unexpected UI changes. Use ngrok for public access and keep both terminals running.

"Method Not Allowed" is normal: The API endpoint should reject browser GET requests as a security feature. Always test with POST requests.

Pro Tips

  1. Keep Flask and ngrok running during evaluation
  2. Test the /test endpoint before submission
  3. Create a test repo before submitting
  4. Enable GitHub Pages manually if auto-enable fails
  5. Monitor Flask terminal during evaluation
  6. Save your ngrok URL (it changes if you restart)
  7. Use UptimeRobot to keep service alive (optional)
