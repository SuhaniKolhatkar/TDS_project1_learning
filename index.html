TDS Project 1 Learnings

Building a GitHub Pages Automation Project

Recently, I worked on automating GitHub Pages deployment and faced several challenges along the way. Here are the key lessons I learned that might help others on a similar journey.

1. Tool Choice & Environment Setup

What went wrong:
Initially tried using Replit, but the new interface had changed, making setup confusing.
Solution:
Switched to VS Code with a local environment for better control and debugging.
Key Takeaway:
Always adapt tools based on practicality. Running projects locally gives full access to logs, environment variables, and dependency control.

2. API Hosting

What went wrong:
Tried to test with localhost URLs, which aren't publicly accessible.
Solution:
Used ngrok to expose the local Flask server to a public HTTPS URL.
Key Takeaway:
Ngrok is essential for making local APIs publicly accessible. It bridges local development with external integrations.

3. API Endpoint Testing

What went wrong:
Opened the API endpoint in browser and got "Method Not Allowed" error.
Solution:
Realized the endpoint only accepts POST requests, not GET.
Key Takeaway:
Always check the allowed HTTP methods for API endpoints. Browsers send GET requests by default.

4. OpenAI API Key Issue

What went wrong:
Tried to use OpenAI API key, which required paid credits.
Solution:
Switched to Google Gemini API, which is free and works well.
Key Takeaway:
Evaluate API costs and accessibility before integration. Gemini provides a great free alternative.

5. Gemini Model Selection

What went wrong:
Used outdated model name 'gemini-pro'.
Solution:
Updated to 'gemini-2.0-flash-exp'.
Key Takeaway:
Always verify the latest model names in API documentation.

6. GitHub Token Permissions

What went wrong:
Used a fine-grained GitHub token with limited permissions.
Solution:
Generated a Classic Token with full permissions.
Key Takeaway:
For automation via APIs, use Classic Personal Access Tokens with proper scopes.

7. Repository Initialization Conflict

What went wrong:
Used auto_init=True which caused file conflicts.
Solution:
Set auto_init=False and manually created files.
Key Takeaway:
Avoid auto_init=True when adding files later programmatically.

8. Testing and Validation

What went wrong:
Faced 405 and 503 errors due to Flask not running during ngrok connection.
Solution:
Restarted both Flask and ngrok together.
Key Takeaway:
Always confirm both services are active together before testing.

9. Understanding API Status Codes

What went wrong:
Misunderstood HTTP codes initially.
Solution:
Learned their meaning and used them for debugging.
Key Takeaway:
HTTP codes are your debugging guide. 405 means wrong method, 503 means server not running.

10. GitHub Pages Activation

What went wrong:
GitHub Pages didn't auto-enable after repo creation.
Solution:
Manually enabled it in repo settings.
Key Takeaway:
Always verify GitHub Pages deployment manually after setup.

Security Best Practice

Keep all API keys private and never commit them to GitHub. Use environment variables and .gitignore to protect sensitive information.

Final Note

The test endpoint is for self-verification only. True success is proven by a working GitHub Pages site and successful repo creation.

Every challenge was a learning opportunity. Happy coding!
